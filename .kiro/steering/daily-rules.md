# Daily 작업 규칙

## 파이프라인 라우팅

파일명이 주어지면 아래 규칙으로 파이프라인을 자동 판별해 설명 없이 즉시 실행한다.
동사는 필요 없다. 여러 파일이 주어지면 각각 처리한다.

- 이름이 `_raw.txt`로 끝남
    → pipeline/raw_messenger/_00_process.script.py <파일>
      split(00a) → raw_init(01) → normalize(02) 통합 실행.
      · 00a 날짜 분리 + 제목 교정(무손실): 타임스탬프(YYYY-MM-DD)를 유일한 진실로,
        각 메시지를 그 날짜의 정규 경로 YYYY/MM/DD/_YYYYMMDD_<이름>_raw.txt로 귀속.
        - 다른 날짜 블록 → 그 날짜 정규 경로로 이동. non-TS 연속줄은 앞 TS의 날짜에 귀속.
        - 대상이 없거나 비어 있으면 생성/채움. 이미 내용이 있으면 타임스탬프 기준 union 병합
          (덮어쓰기·중복제거 없음 = 무손실). 절대 덮어쓰지 않는다.
        - 소스가 자기 이름날짜(정규 경로) 내용을 하나도 안 가지면(제목 틀림) → 전부 이관 후 소스 제거.
        - plan→검증(줄 수 보존)→commit 순. 무손실 검증 실패 시 아무것도 변경 않고 중단.
      · 분리된 원본 + 신규 각 파일에 01→02 실행. 어떤 파일의 01이 중단(확인 필요 exit 2 / 오류)하면 그 파일 02는 건너뜀.
      · 01이 하루치 '-- N개.' 집계를 붙이고, 02가 _normalized.txt 생성 + 손실 게이트.
- 그 외 일기 .txt (예: 20260708.txt, 20260702_발표.txt, 20260701_형.txt)
    → pipeline/ai_analysis/_refine.script.py <파일>

### VCS 자동 스테이징

_00_process 와 _refine 은 처리 성공 후 결과 파일을 git 스테이징한다.
  · _00_process: 결과 raw + _normalized + 분리 생성 파일, 제목교정으로 삭제된 소스는 삭제까지.
  · _refine: 정제한 파일.
  · best-effort — git repo가 아니면 조용히 건너뜀. 스테이징까지만(커밋은 사람이). _01/_02/_00a 자체는 순수.

### 명시적 상위 지정 (자동 판별보다 우선)

- "raw만" / "01만"       → _01_raw_init.script.py <파일>   (집계까지만, normalize 안 함)
- "normalize만" / "02만" → _02_normalize.script.py <파일>  (집계 없이 normalize만)
- "refine"               → _refine.script.py <파일>

## 파일 최신 버전 검증 규칙

이 규칙을 어기면 작업 결과 전체가 무효다. 예외는 존재하지 않는다.

- 스크립트 실행 전: 반드시 Read 도구로 대상 파일을 읽어 현재 상태를 직접 확인한다.
- 스크립트 실행 후: 반드시 Read 도구로 결과 파일을 읽어 출력이 올바른지 확인한다.
- 세션 요약·맥락·이전 기억에서 파일 상태를 "안다"고 판단하는 것을 금지한다. 요약은 과거 스냅샷이며 현재 파일 상태가 아니다.
- Read 없이 실행한 스크립트는 결과가 맞더라도 규칙 위반이다.
- Read 결과가 예상과 다르면 즉시 멈추고 사용자에게 보고한다. 우회 시도 금지.
- bash 결과보다 Read 결과를 우선한다.
