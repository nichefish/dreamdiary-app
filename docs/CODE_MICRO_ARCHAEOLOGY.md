# 코드 감식 (Software Forensics) — 주장 심문·평결·은행화

> 소스코드 고고학 **가문**의 감식(forensics) 편. 거시 편([`CODE_ARCHAEOLOGY.md`](CODE_ARCHAEOLOGY.md))과 **증거·산출물은 공유하되 질문 생성·성공조건·종료조건은 공유하지 않는다** — 별개 방법론이다.
> **스택·제품 비종속.** 특정 저장소의 수치·파일명·도메인명은 본문에 두지 않는다. 실물은 각 저장소의 `digs/`에만.

이건 "작은 역사"가 아니다. **역사를 쓰는 일이 아니라, 저장소에 대해 우리가 믿는 개별 주장을 1차 사료로 심문하는 일**이다. 시간축은 필요할 때 꺼내 쓰는 **증거축 하나**일 뿐, 대상이 아니다. 그래서 이름은 고고학 가문에 남되, 하는 일은 미시사가 아니라 **software forensics / empirical code investigation**이다.

---

## 거시(사료편찬) vs 미시(감식) — 다른 인식론적 작업

| | 거시 — 사료편찬 (historiography) | 미시 — 감식 (forensics) |
|---|---|---|
| 함수 | 흩어진 사료 → 시간·소유·구조축 압축 → 가장 설명력 높은 역사 모델 | 주장 하나 → kill-test → 1차 사료 공격 → 평결 |
| 가치 | **종합(synthesis)** | **분해·판별(discrimination)** |
| 성공조건 | 정합적 서사 | kill-test 통과/실패 |
| 재실행 | 안정 모델로 **수렴**(정상) | 대상이 계속 새 주장을 뱉어 **지속** |
| 도구 | git·blame·pickaxe·코드 | 같음(+DB·운영자료) |

도구가 같다고 방법론이 같은 게 아니다. 탐정과 역사가는 같은 문서고를 뒤지지만 같은 학문이 아니다. **기준은 "현재 vs 과거"가 아니라 "정합적 서사가 목표냐(사료편찬) vs kill-test 통과가 목표냐(감식)"** 이다 — 과거에 대한 주장도 kill-test가 있으면 감식이다.

## 관계 — 증거 공유, 진리규칙 비공유, 양방향

```
              ┌──────────────┐
      ┌──────→│   거시 지도    │──────┐
      │       └──────────────┘      │
 확정 사실·정정                    주장·이상점
      │       ┌──────────────┐      │
      └───────│   미시 감식    │←─────┘
              └──────────────┘
   증거 저장소(git·코드·DB·HISTORY·system-issues) = 공유
   산출물 코퍼스(digs·HISTORY·system-issues)     = 공유·교차링크
   진리 판정 규칙(성공·종료조건)                  = 비공유
```

거시는 미시에게 **후보 주장·이상점**을 주고, 미시는 거시에게 **확정 사실·정정**을 돌려준다. 부모-자식이 아니라 상호 공급. **단, 서로의 성공조건을 상속하지 않는다.**

## 루프

`SEED(반증가치 있는 주장) → 가설(반증조건) → 고증(1차 사료) → 평결(VERDICT) → [분기: 선택] → 은행화 or 닫음`

### ① SEED — 어디서든
시드는 **반증할 가치가 있는 주장**이다. 출처는 거시 지도·`system-issues`·코드 냄새·운영 현상·기존 발굴·테스트 부재 — 무엇이든.
> ★ **출처는 신뢰도를 상속하지 않는다.** `HISTORY`에 `[확정]`으로 적혀 있어도 DIG에 들어오는 순간 다시 피고인이다. (경험상 최고 수익 발굴은 거시의 **부재-주장**("결함 없음"·"안정"·"커버됨")을 공격해서 나온다.)

### ② 가설 — 반증가능·원자적
무엇이 관찰되면 이 주장이 틀리는가(**반증조건**)를 문장으로 쓸 수 있어야 한다. 반증조건 없는 서사는 감식이 아니다. 좋은 시드일수록 kill-test가 쿼리 하나로 떨어진다.

### ③ 고증 — 1차 사료로 공격

| 사료 | 도구 | 죽이는 것 |
|---|---|---|
| 역사 상태 A/B | 두 시점 파일 비교, 구버전 실행 | "이 커밋이 원인" 회귀 주장 |
| 도입 시점 | pickaxe (`log -S`) | "언제부터" 타이밍 주장 |
| line authorship | `blame -w -M -C` | 현재 남은 줄을 누가 작성했는가 (`-M -C`=이동/복사 추적 개선 = line provenance 정확화이지 "의미·이해 소유" 아님) |
| 변경 부호 | `-w` numstat 순삭제(net−) vs 순추가 `+N/−0` | build-through(재작성) vs build-around(접붙임) **후보** 탐색 |
| 명분-diff 불일치 | 커밋 메시지 액션절 vs `-w` numstat 규모 | **scope mismatch**: 메시지 범위("로깅/오타 추가")≪실제 재작성 = 커밋 메시지를 **변경 동기의 완전한 기술로 신뢰하지 말라는 경고**일 뿐. *왜* 커졌는지(조사중 자연증가·squash·계획됨·재량…)는 코드로 모름 — 동기 귀속 금지([관측층위 비약 금지]) |
| 실행 경로 | 코드 직독·호출그래프·포인트컷 | "무엇을 부른다/안 부른다" 결합 주장 |
| 운영 상태 | DB 조회 | 코드만으로 불가한 매핑·비율·실제 상태 |
| 이슈·티켓 | 트래커 조회, 커밋-티켓 참조 | 당시 문제정의·요구·논쟁·대안·정당화의 **REC 사료**. `REC[확정]`≠`WORLD` — 기록된 이유를 실제 원인과 동일시 금지(계약 §1). REC와 diff의 불일치 자체가 사료 |

**금지: diff·커밋 메시지·기억만으로 은행화.** 각 주장에 증거등급: `[확정]`/`[강한추정]`/`[약한추정]`/`[미확인]`.

### ④ 평결 (VERDICT)
가설은 **지지/기각/분해/미결** 중 하나로 판정하고, **무엇까지 말할 수 있고 무엇부터 말할 수 없는지**를 적는다. kill-test는 깨끗한 확증을 거의 안 주므로 대개 분해·미결이다.
★ **보존하는 것은 조사의 논리이지 문서의 버전 역사가 아니다.** 죽은 가설은 *이 문서 안에 명시된 H가 증거로 죽는* 형태(H → 반증하는 E → 최종 평결)로 남긴다 — self-contained이며 `digs/`의 존재 이유다. 반면 "초판에서는·이전에는·우리가 처음엔·재검증 노트" 같은 **문서 밖 버전 역사는 넣지 않는다**(→ Git이 담당). ([자기완결] invariant)

### ⑤ 분기 — 선택이지 강제 아님
가지가 나오면 프론티어에 적재. **안 나오면 닫는다.** 발산을 강제하지 않는다 — 강제하면 쓰레기 가설도 발산한다. (발산이 계속되는 것은 강제 때문이 아니라 **시드 출처가 살아있는 코드베이스(무한·갱신)**이기 때문이다. ①에서 출처를 열었기에 ⑤의 강제가 불필요해졌다 — 두 규칙은 커플이다.)

### ⑥ 은행화 or 닫음
산출을 목적지로: 실행가능→`system-issues`/`TODO` · 이해→`HISTORY` · 재도출 비쌈→메모리. **거시 지도의 어느 문장을 보강/정정하는지 역링크.**
산출이 없으면 태그를 달아 닫되 — ★ **닫음 게이트: 실행한 kill-test와 "왜 더 안 파는가"를 기록.** 안 하면 조기종료가 "없더라"로 위장된다.

## 산출 태그 (직교·복수 허용, 서열 아님)

출력의 **종류**. `T1~T4` 서열은 폐기 — 숫자는 "발견 없음"을 실패로 취급하게 만든다.

| 태그 | 뜻 |
|---|---|
| `[DEFECT]` | 신규 실행 결함 |
| `[STRATEGY]` | 처방/작업순서 변경 |
| `[MECHANISM]` | 생성 메커니즘 발견 |
| `[CORRECTION]` | **외부 코퍼스**(HISTORY·system-issues·다른 발굴)의 주장/사실을 바꾸는 산출. SEED에서 무엇을 정정하는지 명시. *자기 문서의 작성사는 아님* |
| `[CORROBORATED]` | 주장을 공격했으나 살아남음 — **양성 결과(주장 강화)** |
| `[INCONCLUSIVE]` | 증거 자체를 못 얻음 |
| `[METHOD]` | (선택) 재사용 가능한 조사 기법 산출 |

- ★ **`[CORROBORATED]`는 실패가 아니라 가장 과학적인 양성 결과다.** 공격받고 버틴 주장은 이제 더 믿을 만하다. "발견 압력"이 예쁜 서사(가짜 발견)를 낳는데, 이 태그가 그 무의식적 인센티브를 막는 안전판이다.
- ★ **태그축(무엇을 냈나) ⊥ 증거등급축(얼마나 확실한가).** 한 `[DEFECT]`도 메커니즘은 `[확정]`, 폭발반경은 `[강한추정]`일 수 있다. 두 축을 겹치지 마라.

## 프론티어 — 발산 보증이 아니라 탐색 상태 보존

`digs/README.md`가 든다: **닫힌 발굴(태그) · 열린 가설(기대수익 순) · 각 발굴의 `[미확인]`.**
목적은 **이미 판 곳 재방문 방지 + 다음 표적 보존**이지 "매번 새것 강제"가 아니다.

> 초기 미시 방법론의 물음은 "어떻게 매번 새것을 발견하게 만들까"였다. 성숙한 물음은 **"발견이 없을 때도 없다고 말할 수 있게 만들까"** 이다. 후자가 훨씬 과학적이다.

종료조건은 강제 발산이 아니라 **기대수익 < 고증 비용**이다.

## 산출물 — 발굴 1건 = 문서 1개

```
# DIG-NNN — <한 줄 제목>
태그           [DEFECT]/[STRATEGY]/[MECHANISM]/[CORRECTION]/[CORROBORATED]/[INCONCLUSIVE] (복수)
발단(SEED)     어떤 주장 + 출처(출처는 신뢰도를 안 준다)
가설           반증가능 형태 + ★반증조건 (H가 문서 안에 명시돼 이후 kill이 self-contained)
고증           증거 사슬(사료·도구·등급)
평결           H 지지/기각/분해/미결 + 무엇까지 말할 수 있나 (문서 밖 버전역사 금지)
은행화/닫음    → 어느 사실 문서의 무엇으로 (역링크) / 또는 닫음 게이트(실행 kill-test + 왜 중단)
파생 가지      프론티어로 (없으면 "없음")
미확인         남긴 [미확인]
```

문서 스택의 누락된 중간층: `HISTORY`(과거) → **`digs/`(어떻게 아는가)** → `system-issues`(현재) → `TODO`(처방).

## 판정 invariant

| 판단 | 축 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 반증가능성 | 가설 | 명시적 반증조건을 건다 | 반증 불가능한 서사를 감식이라 부르기 |
| 무출처특권 | 시드 | 출처 무관하게 주장을 피고인으로 삼는다 | `HISTORY` `[확정]`을 검증 없이 신뢰(시드가 신뢰도 상속) |
| 1차 사료 | 고증 | A/B·pickaxe·blame(`-w -M -C`)·코드·DB로 죽인다 | diff·커밋메시지·기억만으로 은행화 |
| 부호=신호 | 변경성격 | 순삭제/`+N−0`를 build-through/around **후보**로만 | 부호 단독으로 소유·이해 판정 (blame×위치×거동×티켓 교차검증 필수) |
| **Comparison Eligibility / Jurisdiction Gate** ★ | 비교 | 비교 대상이 동일한 관할·역할·semantic proposition에 속하는지 먼저 입증한다 | 관할 밖 경로의 부재를 우회로, 의미가 다른 구조 차이를 불일치로, proposition이 다른 반복 표현을 중복으로 판정 |
| **관측층위 비약 금지** ★ | 추론 | 각 전이(`artifact → 구조관찰 → behavior`)마다 adequacy를 확인한다 | 전이를 무조건 통과시키기. `+183/−116`이 확정하는 건 "대규모 텍스트 변경"이지 "관통 재작성" 아님(위치·의미 확인 후에야, [부호=신호] 참조). 특히 `behavior → 인지·의도·건강·사회원인`은 별도 사료 없으면 `[INCONCLUSIVE]`. 인스턴스: 무밸런스(churn≠건강)·무이해추론(blame·생존≠이해)·무의도(diff·메시지≠동기)·커밋≠검증된 결정 |
| **현재상태 ≠ 과거원인** | 시간 | 과거 행동엔 pre-change 상태를 복원해 쓴다 | 현재 blame·구조를 과거 변경의 *원인*으로 사용 (지분은 대개 결과변수) |
| 자기완결(document-complete) | 문서 | 조사 논리(H→kill→평결)를 문서 안에 self-contained로 남긴다 | 문서 버전 역사("초판/이전에는/재검증 노트")를 본문에 넣기 — 그건 Git 담당. 문서는 현재 상태만으로 완결돼야 한다 |
| 닫음 게이트 | 종료 | 실행 kill-test + 왜 중단을 기록 | 빈손을 "없더라"로 위장 |
| 발산 비강제 | 프론티어 | 가지 없으면 닫는다 | `≥1 가지` 강제(쓰레기 가설 발산) |
| 교차링크 | 은행화 | 거시 지도의 어느 문장을 보강/정정하는지 명시 | 지도와 따로 노는 고립 발견 |
| REC≠WORLD | 사료 | 기록claim/세계claim을 별도 명제·별도 등급으로 (계약 §1) | 한 등급으로 기록존재와 세계사실을 뭉치기 |
| 관계 별도판정 | edge | 노드가 [확정]이어도 관계명제는 관계 사료로 등급 (계약 §2) | 두 확정 노드 사이 인과·의도를 자동 [확정] |
| 선정독립성 | provenance | admissibility(Q1·Q2·Q3) 통과분만 거시 검증 (계약 §3·§4) | 거시가 지목해 판 표본을 거시 독립검증으로 되먹임 |

### Comparison Eligibility / Jurisdiction Gate

두 대상을 비교해 관계 명제를 만들기 전에 다음 세 질문에 답한다.

1. **Jurisdiction**: 이 경로·구조는 비교 기준이 책임지는 모집단에 실제로 속하는가?
2. **Role**: 두 경로가 같은 lifecycle event·operation·capability를 수행하는가?
3. **Proposition**: 두 표현이 같은 정책 문장을 독립적으로 나타내며 lockstep 변경을 요구하는가?

셋 중 필요한 조건을 입증하지 못하면 개별 관측만 기록하고 bypass·inconsistency·duplication 판정은 보류한다.

- **Path absence ≠ bypass without jurisdiction.** 기준 경로의 관할이 아닌 객체가 그 경로를 타지 않는 것은 우회가 아니다.
- **Structural difference ≠ inconsistency without semantic equivalence.** 다른 사건이나 역할을 수행하는 제어흐름은 모양이 달라도 경쟁 구현이 아니다.
- **Repeated representation ≠ duplication without proposition equivalence.** 같은 enum 값을 포함한 집합도 서로 다른 capability 질문에 답하면 동일 정책의 재선언이 아니다.

이 Gate는 측정 불변과 다른 축이다. 측정 불변은 같은 metric을 같은 연산으로 재는가를 검사하고, Comparison Eligibility는 정확히 잰 두 대상 사이에 **비교 관계를 붙일 자격이 있는가**를 검사한다.

## 감식 → 미시사 → 거시 인터페이스 계약 (실행 명세)

> 상태 없는 다른 조사자가 이 절만으로 deterministic하게 적용할 수 있게 쓴다. 감식 산출을 미시사·거시로 넘길 때의 등급·관할 계약이다. 미시사 층 문서는 이 계약 위에서 결정된다.

**0. 등급 어휘 (단일).** 전 층 공통 `[확정]/[강한추정]/[약한추정]/[미확인]`. 새 어휘를 만들지 않는다. 아래 규칙은 이 넷으로만 등급을 말한다.

**1. REC / WORLD 분리.** 한 사료(이슈·커밋 메시지·주석)는 **두 개의 별개 명제**를 낳는다. 등급 하나를 나눠 갖지 않는다.
- `REC[등급]`: 「…라고 기록되어 있다」(기록의 존재).
- `WORLD[등급]`: 「기록된 그것이 실제였다」(세계의 사실). `REC`가 `[확정]`이어도 `WORLD`는 독립 판정.
- `REC`와 `WORLD`의 불일치 자체가 1급 사료다.
- 예: 티켓 「범용성 개선을 위해 리팩터」 → `REC[확정]: 티켓에 '범용성 개선' 기록` + `WORLD[약한추정]: 실제 동기에 범용성 포함`. diff가 고객별 분기 +600이면 `WORLD`를 내린다.
- 고증 사료표의 **명분-diff 불일치**(scope mismatch) 행과 관측 한계 **사회층**(git은 사회적 협상의 결과를 기술적 사실처럼 기록)은 이 규칙의 인스턴스다.

**2. node/edge 등급 + edge rubric.** 노드(명제)뿐 아니라 **엣지**(관계 명제: 인과·의도·생성규칙)도 자기 등급을 별도로 받는다.
- Invariant: `A[확정] ∧ B[확정]`이라도 `A→B`가 자동으로 `[확정]`이 되지 않는다. 관계는 **관계 자체의 사료**로 판정한다.
- 엣지 증거유형 → 등급 **상한**:
  - 직접연결(관계를 직접 지지하는 동시대 사료, 교차확인) → 상한 `[확정]`
  - 구조적추론(관계 직접사료 없음, 시간순·변경형태·대안배제가 동일 설명으로 수렴) → 상한 `[강한추정]`
  - 서사적가설(관측을 설명하나 경쟁설명이 살아있음) → 상한 `[약한추정]`
- 미시사 명제 등급 = `min(노드들, 엣지)`. 서사로 상한을 넘지 못한다.
- 예: `[확정] 예외 분기 추가` →(구조적추론: 3년 뒤 동형 재현 + 일반화 시도 기각 교차)→ `[강한추정]` 「국소 흡수 생성규칙」. 노드가 확정이어도 엣지가 강한추정이면 결론은 강한추정.

**3. provenance 최소 필드 + 독립성 admissibility.** 모든 미시 타일이 기록한다.
- `선정계기`: 이 타일이 왜 선택됐는가 — 지목한 거시가설 H, 또는 H와 무관한 규칙(장애·무작위·기계표본).
- `사실등급`: 타일 내부 명제들의 등급(감식 산출).
- 독립성은 **계수가 아니라 통과/불통과 test**: `Q1` 선정 전에 H가 있었나 · `Q2` H가 이 타일의 선정확률을 올렸나 · `Q3` H가 없었어도 같은 규칙으로 선택됐을까. 판정: `Q2=Yes ∧ Q3=No` → **inadmissible**(탐색 전용). `Q3=Yes` → admissible. 불명 → 독립성 `[미확인]`.
- 이 test는 [무출처특권](출처는 진리를 안 준다)의 형제다. 세 직교축: **등급**(얼마나 확실) / **출처**(진리를 안 준다) / **선정**(독립성을 안 준다).
- 예: 거시가 「build-around 시대」라 지목해 판 파일 → `Q2=Yes, Q3=No` → inadmissible. 장애에서 우연히 뜬 같은 구조 → `Q3=Yes` → admissible.

**4. 탐색 evidence / 검증 evidence 구별.** 거시가 지목해 파는 것 자체는 정당한 **탐색**이다. 죄는 그 결과를 **독립 검증 증거**로 거시에 되먹이는 것이다. inadmissible 타일은 기록·서사에 쓰되 거시 posterior를 **움직이지 못한다**. admissible 타일만 §5로 넘어간다.

**5. 미시 → 거시 directional update.** 숫자 임계 없음.
- 경쟁가설 쌍을 명시한다(예: `H1`=시대의 지배적 생성규칙 존재 vs `H2`=사례별 국소 대응, 시대적 규칙 없음).
- admissible 타일마다 기록: 사실등급 / 선정독립성 / `H1`·`H2` 판별력 / 기존 타일과의 사료·인과 중복.
- 판정: `H1↑ / H1↓ / neutral / inadmissible` 중 하나. **중복 타일은 판별력을 새로 더하지 않는다.**
- 거시 모델 수정은 「posterior가 충분히 움직였다」는 판단에서 오며, `N개면 수정` 같은 가짜 객관성으로 위장하지 않는다.

**6. §16 ↔ 미시사 관할.** 거시 편 [`CODE_ARCHAEOLOGY.md`](CODE_ARCHAEOLOGY.md) §17에 둔다. 경계는 대상 수가 아니라 산출물의 질문 — 같은 단일 객체라도 「객체의 becoming」이면 §16, 「객체를 렌즈로 한 시대·구조 주장」이면 미시사.

## 관측 한계 — git으로 판정 불가한 것 (선언된 사각)

감식은 코드·git·DB만 본다. 아래는 그 사료에 **원리적으로 없는 것**이다 — 추론하지 말고 사각으로 선언한다.

- **이해·건강**: 코드 shape는 활동량이지 이해도·건강도가 아니다. 왕성한 churn이 건강한 개발인지 고통스러운 thrashing인지, 변경자가 코드를 실제로 이해했는지는 git에 없다.
- **사회층**: 책임 전가, 분쟁, 의도, 후회, "누가 무엇을 강하게 밀었나", 왜 누가 이 코드를 이후 기피하는가 — 전부 불가시. **git은 사회적 협상의 결과를 기술적 사실처럼 기록한다**(수긍한 삭제도 "삭제"로 남는다).

### 소유는 한 변수가 아니다

"소유"로 뭉뚱그리지 않는다. 최소 다섯이며 git 관측도는 제각각이다:

| 종류 | 뜻 | git 관측 |
|---|---|---|
| line/blame authorship | 현재 남은 줄의 저자 | **완전**(`blame -w -M -C`) |
| maintenance ownership | 누가 이슈를 실제로 받는가 | **부분**(커밋-티켓 참조로 추정) |
| epistemic ownership | 누가 행동을 설명할 수 있는가 | 없음 |
| social ownership | 문제 시 누구 책임으로 귀속되는가 | 없음 |
| willing ownership | 누가 다시 손대려 하는가 | 없음 |

★ **`blame -w -M -C`는 "의미/이해 소유"가 아니라 line authorship이다** — 재포맷을 중화한 정확한 *줄 저자*일 뿐. 높은 blame 지분이 유지보수 의사(willing)와 공존하지 않을 수 있다(많이 건드려 지분이 높아졌으나 그 경험 때문에 다시는 안 건드리려는 상태). 코퍼스에서 "소유"를 쓸 땐 어느 종류인지 한정한다.

> ★ **감식은 검증된 증거 사슬을 넘어 서사를 연장하지 않는다.** `A[확정] → B[확정] → C[확정]`(각 화살표가 코드·프레임워크로 검증됨)은 정당한 `[MECHANISM]`이다 — 예: 예외 삼킴→정상 반환→인터셉터 미감지→커밋. **금지는 사슬 끝에 독립 사료 없는 화살표를 붙이는 것**: `… → "그러므로 개발자가 이해 못했다 / 건강하다 / 이렇게 될 수밖에 없었다"`. 마지막 전이에 사료가 없으면 거기서 **멈추고** `[INCONCLUSIVE]`. (서사 자체가 아니라 *증거를 넘어선* 서사가 금지다.)

### 성공의 정의

목표는 **실제 역사를 맞히는 것이 아니다**(코드만으론 불가능). 목표는 **코드만 있을 때 틀린 이야기를 만들어내지 않는 것**이다. 완벽한 code-only 감식자는 실제 경위를 하나도 못 맞혀도 — `[확정]`은 코드가 받치는 것만, 나머지는 `[미확인]` — **하나도 헛소리하지 않으면 성공**이다.
오라클(현장에 있던 인간의 증언)은 이 프로토콜의 *요건이 아니다*. 오라클은 **방법론 개발 단계의 calibration**(어느 룰이 비약을 못 막았나를 사후에 드러냄)에만 쓰고, 개별 감식이 오라클을 필요로 하게 만들지 않는다.

**방법론 품질의 척도** = 문서가 얼마나 그럴듯하냐가 아니라, **다음번에 실제 사정을 모른 채 얼마나 적게 거짓말하는가.** 감식이 제대로 되면 산출물은 점점 **작고 건조해진다**(그럴듯한 서사가 줄고 `[확정]`·`[미확인]`만 남는다) — 그게 건강한 신호다.
