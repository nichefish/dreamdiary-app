# Confluence 로컬 적재 작업 계약

## 1. 명령 해석

사용자가 **Confluence 페이지 또는 폴더 링크와 함께 `적재해`, `로컬에 적재해`, `파일로 적재해`처럼 적재 의사를 명시하면**, 해당 요청은 아래 정형 작업 전체에 대한 실행 승인이다.

- Atlassian API/커넥터로 페이지를 읽는다.
- 저장소의 기존 Confluence 미러 위치를 찾는다.
- 페이지 본문을 로컬 Markdown 파일로 저장한다.
- 해당 미러가 사용하는 `index.json`의 페이지 메타데이터를 원격 현재 상태와 맞춘다.
- 아래 검증 절차까지 완료한다.

### 1.1 하위 트리 증분 적재

사용자가 Confluence 페이지·폴더 링크 또는 아래 별칭과 함께 **`하위 문서도 싹 적재해`**, **`아래 문서 전체 적재해`**처럼 하위 범위를 명시하면, 대상 컨테이너의 하위 폴더를 포함한 전체 페이지 트리를 로컬 미러와 증분 동기화하라는 명시적 실행 승인이다.

1. 대상 컨테이너의 하위 폴더와 페이지 전체 목록을 읽기 전용으로 조회한다. 대상이 페이지이면 그 페이지 본문도 적재 범위에 포함하고, 대상이 폴더이면 폴더 아래의 페이지를 적재 범위로 삼는다.
2. 원격 목록의 `lastModified`는 변경 후보를 빠르게 선별하는 힌트로만 사용한다.
3. 후보 페이지의 원격 `pageId`와 `version.number`를 로컬 `index.json`과 비교해 최종 변경 여부를 판정한다. 지역화된 `lastModified` 문자열만으로 본문 갱신을 확정하지 않는다.
4. 로컬에 없는 신규 페이지와 원격 `version.number`가 더 높은 기존 페이지만 본문을 조회하여 저장한다.
5. 새 페이지는 원격 상대 계층에 `${pageId}__${안전한 제목}.md`로 추가한다. 갱신 페이지는 제목이 바뀌어도 기존 `file` 경로를 유지한다.
6. 대상 페이지의 현재 메타데이터, 미러 집계, 폴더 스냅샷 집계와 `collectedAt`을 동기화한다.
7. 댓글 본문과 `*.comments.json`은 사용자가 댓글 적재까지 요청한 경우에만 조회·생성·갱신한다.

### 1.2 하위 트리 적재 별칭

다음 별칭은 페이지 링크 없이 지정된 컨테이너를 선택하고 1.1의 동일한 하위 트리 증분 적재 규칙을 적용하라는 명시적 실행 승인이다.

- **`희승님 CSR 문서 적재해`**: `daily/text/raw/confluence/최희승/index.json`의 `folderSnapshots`에서 제목과 `relativePath`가 `CSR 현황`인 단일 항목을 찾아 대상으로 사용한다.
- **`LES 리메이크 문서 적재해`**: `daily/text/raw/confluence/연구솔루션팀/index.json`의 `folderSnapshots`에서 `relativePath`가 `LIMS/LES 리메이크`인 단일 항목을 찾아 대상으로 사용한다.
- **`직책자회의 문서 적재해`**: `daily/text/raw/confluence/GxP 사업부/직책자회의/index.json`의 `source.rootFolderId`와 `scope.rootSnapshot`이 가리키는 단일 루트 폴더를 대상으로 사용한다.

별칭은 폴더 ID를 계약 문서에 고정하지 않는다. 대상 `folderSnapshots` 또는 루트 메타데이터가 없거나 여러 항목으로 갈려 하나로 확정되지 않을 때만 사용자에게 대상 위치를 질문한다.

이 정형 작업에는 `AGENTS.md`의 일반적인 수정 직전 승인 질문을 다시 적용하지 않는다. 위 실행 트리거에 해당하지 않거나 저장 위치가 여러 곳으로 갈려 결정할 수 없는 경우에만 질문한다.

## 2. 기본 저장 위치 결정

1. URL의 페이지 또는 폴더 ID를 추출한다. 예: `/pages/449675274/...` → `449675274`, `/folder/440270878/...` → `440270878`.
2. `daily/text/raw/**/index.json`에서 `pageId` 또는 `sourceUrl`이 일치하는 항목을 먼저 찾는다.
3. 기존 항목이 있으면 그 항목의 `file` 경로를 정답으로 사용한다. 파일 내용을 최신 원문으로 교체하고 같은 항목의 제목·상태·버전 등 API가 제공한 현재 메타데이터를 동기화한다.
4. 기존 항목이 없으면 API로 페이지의 스페이스와 상위 페이지 계층을 확인하고, 기존 로컬 미러 구조와 동일한 디렉터리에 `${pageId}__${안전한 제목}.md`로 저장한다.
5. 새 페이지의 로컬 위치가 기존 계층만으로 하나로 확정되지 않을 때만 사용자에게 저장 위치를 질문한다. 임의의 새 최상위 분류를 만들지 않는다.

### 2.1 하위 트리의 이동·삭제·제목 변경

- 원격 트리 안에서 페이지나 폴더가 이동하면 `relativeAncestors`, `file`, `commentsFile`과 로컬 파일 경로를 새 상대 계층에 맞춰 함께 이동한다.
- 페이지 제목만 바뀌면 `title`과 원격 메타데이터를 갱신하고 기존 로컬 파일명과 `file` 경로는 유지한다.
- 원격 목록에서 사라진 기존 페이지는 권한 변경, 일시적 조회 실패, 삭제, 휴지통 이동, 대상 트리 밖 이동을 목록 부재만으로 구분할 수 없으므로 자동 삭제하지 않는다. `index.json`에 원격에서 확인된 상태 또는 `remoteMissing`·`outOfScope` 판정과 확인 시각을 기록한다.
- 사용자가 **완전 동기화와 로컬 제거를 명시적으로 요청한 경우에만**, 원격 삭제 또는 대상 트리 이탈이 확인된 파일과 인덱스 항목을 제거한다. 제거 전 정확한 대상 경로와 원격 상태를 읽기 전용으로 재확인한다.

## 3. 원문 저장 계약

- 본문은 요약·재작성·번역하지 않고 API가 반환한 현재 원문을 Markdown으로 보존한다.
- 표, 체크박스, 링크, mention·smartlink 등의 Confluence 표현은 정보가 유실되지 않게 유지한다.
- 파일은 UTF-8 BOM 없음으로 저장한다.
- 기존 파일을 갱신할 때 페이지 ID가 같은지 확인한 뒤 교체한다.
- `index.json`에는 원격 페이지의 현재 `pageId`, `title`, `status`, `sourceUrl`, `createdAt`, `version`, 로컬 `file` 경로를 정확히 반영한다.
- 댓글 본문과 `*.comments.json`은 사용자가 댓글까지 요청한 경우에만 신규 생성하거나 갱신한다.
- 다른 페이지, 다른 인덱스 항목, 다른 세션이 만든 워킹트리 변경은 건드리지 않는다.

## 4. Confluence에서 허용되는 동작

적재는 **읽기 전용 수집**이다. Confluence에는 API 접근 로그 외 상태 변화를 남기지 않는다.

허용:

- 페이지 검색·조회
- 페이지 메타데이터·상위 계층 조회
- 사용자가 댓글 적재까지 요청한 경우의 댓글 조회

금지:

- 페이지 생성·수정·삭제
- 댓글 작성·수정·삭제
- 좋아요·반응·팔로우·구독
- 권한·제한·라벨 변경
- 작업 보고나 완료 흔적 게시

## 5. 사용하지 않는 우회 경로

- 인앱 브라우저나 외부 브라우저를 열지 않는다.
- 사용자를 Confluence 또는 로컬 DreamDiary 로그인 화면으로 보내지 않는다.
- 로컬 DreamDiary 애플리케이션 API나 DB에 저장하지 않는다.
- 원문 전달용 임시 파일, 스크립트, 보고서, 별도 작업 문서를 만들지 않는다.
- Atlassian 커넥터가 접근할 수 없으면 브라우저로 우회하지 않고 접근 실패를 보고한다.

## 6. 완료 검증과 보고

1. 대상 Markdown 파일이 존재하고 크기가 0보다 큰지 확인한다.
2. 파일의 제목·주요 첫 구간·마지막 구간을 읽어 응답 원문이 잘리지 않았는지 확인한다.
3. `index.json`의 페이지 ID·버전·파일 경로가 대상 파일과 일치하는지 확인한다.
4. `git diff -- <대상 Markdown> <index.json>`으로 변경 범위와 한글 보존을 확인한다.
5. `python scripts/check_encoding.py`로 UTF-8 게이트를 확인한다.
6. 결과 보고에는 저장한 절대 경로, 원격 버전, 검증 결과만 간결하게 남긴다.
