# 블로그 로컬 적재 작업 계약

## 1. 명령 해석

사용자가 **공개 웹 글(블로그 등) 링크와 함께 `적재해`, `로컬에 적재해`, `파일로 적재해`처럼 적재 의사를 명시하면**, 해당 요청은 아래 정형 작업 전체에 대한 실행 승인이다.

- 대상 URL의 공개 페이지에서 글의 제목·게시일과, 본문이 공개되어 있으면 본문을 읽는다.
- 비밀번호로 잠긴 글은 공개 페이지에서 확정되는 제목·게시일만 자리표시로 저장한다. 사용자가 그 글의 본문을 직접 주면 비밀번호를 넣지 않고 그 원문을 스냅샷에 넣는다.
- 제목·게시일이 없는 비공개·권한 없음 페이지는 연도·월 스냅샷을 만들지 않고, 인덱스에 주소와 비공개만 남긴다. 사용자가 비공개 글의 제목·게시일·본문을 직접 주면 스냅샷을 만든다.
- `daily/text/blog/`의 기존 파일을 갱신하거나 새 Markdown 파일을 생성한다. 주소만 아는 비공개는 인덱스 행만 갱신한다.
- 사용자가 본문 이미지를 말하면 글 스냅샷과 짝인 이미지 폴더를 만든다. 이미지 파일을 주면 그 폴더에 넣는다.
- `daily/text/blog/index.md` 인덱스를 적재된 글만으로 다시 만든다.
- 아래 검증 절차까지 완료한다.

이 정형 작업에는 `AGENTS.md`의 일반적인 수정 직전 승인 질문을 다시 적용하지 않는다. 링크나 적재 의사가 없거나, 페이지가 공개·보호·비공개 중 무엇인지 확정할 수 없거나, 같은 파일명이 다른 `sourceUrl`과 겹칠 때만 질문한다. 사용자가 비공개 본문을 줬는데 글 주소를 확정할 수 없으면 스냅샷은 저장하고 주소는 질문한다.

Confluence 페이지 URL은 [Confluence 로컬 적재 작업 계약](CONFLUENCE_LOCAL_INGESTION.md)을, ChatGPT 대화 URL은 [ChatGPT 대화 로컬 적재 작업 계약](CHATGPT_LOCAL_INGESTION.md)을 적용한다. 그 밖의 공개 웹 글 URL은 이 계약을 적용한다.

## 2. 기본 저장 위치 결정

1. 요청 URL에서 프래그먼트를 제거한다. 페이지가 `rel=canonical` 또는 `og:url`을 제공하면 그 값을 `sourceUrl`로 쓴다. 없으면 정규화한 요청 URL을 `sourceUrl`로 쓴다. 사용자가 본문만 주고 주소가 없으면 `sourceUrl`을 비우고 4~5를 게시일로 적용한다.
2. `daily/text/blog/**/*.md`에서 `index.md`를 제외하고 파일 머리의 `sourceUrl`이 일치하는 기존 파일을 찾는다. 주소만 있는 비공개는 인덱스의 `[비공개]` 행에서 같은 `sourceUrl`을 찾는다.
3. 페이지에서 글 제목과 게시일을 읽는다. 게시일은 `article:published_time`처럼 페이지가 제공한 시각을 우선하고, 없으면 본문 머리의 공개 게시 시각을 쓴다. 사용자가 준 게시일도 같다. 시간대는 `Asia/Seoul`이다. 제목과 게시일이 없고 권한이 없거나 존재하지 않는 페이지이면 주소만 있는 비공개로 두고 4~7을 적용하지 않는다.
4. 연도 폴더는 게시일의 연도 `YYYY`이고, 월 폴더는 게시일의 월 `MM`(두 자리)이다. 파일명은 `yyMMdd_${제목}.md`이다. 제목의 OS 금지 문자(`<>:"/\|?*`)와 끝의 점·공백만 제거한다.
5. 저장 경로는 `daily/text/blog/${YYYY}/${MM}/${yyMMdd}_${제목}.md`이다. 본문 이미지 폴더는 `daily/text/blog/${YYYY}/${MM}/${yyMMdd}_${제목}/`이다.
6. 기존 파일이 있으면 그 파일을 현재 경로 규칙에 맞춘 뒤 내용을 교체한다. 게시일이나 제목이 바뀌면 파일 경로도 현재 값으로 맞춘다. 이미지 폴더가 있으면 같이 옮긴다.
7. 다른 `sourceUrl`이 같은 경로를 쓰면 덮어쓰지 않고 저장 위치를 질문한다.

## 3. 원문 저장 계약

- 기본 적재 범위는 글의 제목·게시일·본문이다. 본문 이미지가 있으면 글 스냅샷과 짝인 폴더에 원본 파일을 둔다.
- 비밀번호로 잠긴 글은 제목·게시일만 자리표시로 저장한다. 머리의 `protected`는 `true`이다. 본문을 사용자가 직접 주면 그 원문을 두고, 없으면 본문 자리에 `보호글. 본문은 적재하지 않음.`만 둔다.
- 주소만 아는 비공개는 제목·게시일·본문 파일을 만들지 않는다. 인덱스 행만 `[비공개] — sourceUrl`로 둔다. 사용자가 비공개 글의 제목·게시일·본문을 직접 주면 스냅샷을 만들고 머리의 `private`는 `true`이다. 주소를 나중에 알면 같은 파일에 `sourceUrl`을 넣고, 주소만 있던 인덱스 행은 이 행으로 대체한다.
- 본문은 요약·재작성·번역하지 않고 페이지의 현재 원문을 Markdown으로 보존한다. 이어진 줄은 빈 줄 없이 줄바꿈만 두고, 빈 단락은 단락 구분으로 옮긴다. HTML 강조는 Markdown으로 옮길 수 있으면 옮기고, 표준 문법이 없으면 원문 텍스트를 유지한다.
- 메뉴, 사이드바, 댓글, 관련글, 툴바, 좋아요·공유·구독 같은 페이지 껍데기는 본문에 넣지 않는다.
- 파일은 UTF-8 BOM 없음으로 저장한다.
- 파일 머리에는 제목, `sourceUrl`, `postedAt`, `fetchedAt`을 둔다. `postedAt`은 게시일, `fetchedAt`은 이번 적재 시각이다. 보호글은 같은 머리에 `protected: true`를 두고, 비공개 스냅샷은 `private: true`를 둔다. 주소가 없으면 `sourceUrl` 줄을 두지 않는다.
- 같은 `sourceUrl`을 다시 적재하면 원격 현재 상태로 기존 파일을 교체한다. 본문이 공개되어 있으면 본문 스냅샷으로 저장하고 `protected`와 비공개 표시를 제거한다. 잠금이 그대로이고 소유자가 준 본문이 있으면 그 본문을 유지하고 제목·게시일·`fetchedAt`만 갱신한다. 소유자 본문이 없으면 자리표시의 제목·게시일·`fetchedAt`만 갱신한다. 비공개가 그대로면 소유자 본문이 있는 스냅샷은 유지한다.
- `daily/text/blog/index.md`는 적재된 글만 담는 인덱스다. 빈 칸을 미리 만들지 않는다. 보호글 자리표시와 비공개 행도 적재 건수에 포함한다. 머리에는 `적재 건수 / 656`을 둔다. 게시일이 있는 행은 게시일 내림차순(최신 위)으로 `YYYY-MM-DD 제목 — sourceUrl`이고, 보호글 행은 `YYYY-MM-DD 제목 [보호] — sourceUrl`이다. 본문이 있는 비공개 스냅샷은 `YYYY-MM-DD 제목 [비공개] — sourceUrl`이고 주소가 없으면 주소를 생략한다. 주소만 있는 비공개 행은 그 아래에 `[비공개] — sourceUrl`이고, 주소의 글 번호 내림차순이다. 글 스냅샷을 저장하거나 갱신한 뒤 연도·월 폴더의 스냅샷 머리와 인덱스의 기존 비공개 행에서 인덱스를 다시 만든다.
- 다른 글, 다른 세션이 만든 워킹트리 변경은 건드리지 않는다.

## 4. 대상 사이트에서 허용되는 동작

적재는 **읽기 전용 수집**이다. 대상 사이트에는 조회 외 상태 변화를 남기지 않는다.

허용:

- 공개 URL의 HTML 또는 렌더된 문서 읽기
- 글 제목·게시일·본문·식별 메타데이터 읽기
- 공개 본문에 붙은 이미지 파일 읽기

금지:

- 로그인, 회원가입, 구독, 댓글, 좋아요, 공유, 팔로우
- 글 생성·수정·삭제
- 로그인·페이월 뒤를 우회해 본문을 읽는 행위
- 비밀번호 입력

## 5. 사용하지 않는 우회 경로

- 로그인·페이월 뒤를 우회하지 않는다. 잠긴 글의 제목·게시일이 공개 페이지에서 확정되면 자리표시를 저장한다. 권한이 없거나 존재하지 않아 제목·게시일을 확정할 수 없으면 인덱스에 `[비공개] — sourceUrl`만 남긴다.
- 로컬 DreamDiary 애플리케이션 API나 DB에 저장하지 않는다.
- 원문 전달용 임시 파일, 스크립트, 보고서, 별도 작업 문서를 만들지 않는다.
- 잠긴 본문을 비우거나 추측·복원한 파일을 만들지 않는다. 잘린 본문을 원문인 것처럼 저장하지 않는다.

## 6. 완료 검증과 보고

1. 공개·보호 글과 본문이 있는 비공개 스냅샷은 대상 Markdown 파일이 존재하고 크기가 0보다 큰지 확인한다. 주소만 있는 비공개는 연도·월 파일을 만들지 않고 인덱스 행만 확인한다.
2. 본문이 있는 스냅샷은 제목·본문 첫 구간·마지막 구간을 읽어 원문이 잘리지 않았는지 확인한다. 보호글은 `protected: true`를 확인한다. 소유자가 준 본문이 있으면 본문 첫 구간·마지막 구간을 확인하고, 없으면 자리표시 문구를 확인한다. 본문이 있는 비공개는 `private: true`와 본문 첫 구간·마지막 구간을 확인한다. 주소만 있는 비공개는 인덱스 행이 `[비공개] — sourceUrl`인지 확인한다.
3. 공개·보호 글은 파일 머리의 `sourceUrl`이 대상 글과 일치하고, 경로의 `YYYY`/`MM`/`yyMMdd`가 `postedAt`과 일치하는지 확인한다. 본문이 있는 비공개는 경로의 `YYYY`/`MM`/`yyMMdd`가 `postedAt`과 일치하는지 확인한다.
4. `git diff`로 계약 문서와 규칙 파일 외 변경을 만들지 않았는지 확인하고 한글이 보존됐는지 확인한다. `/daily` 스냅샷은 git 추적 대상이 아니다.
5. 대상 스냅샷과 계약 문서를 UTF-8 BOM 없음으로 읽을 수 있는지 확인한다. 계약 문서는 `python scripts/check_encoding.py`로 확인한다.
6. 인덱스 행 수가 적재된 글 수와 같고, 머리가 `N / 656`인지 확인한다. 보호글 자리표시는 인덱스 행에 `[보호]`가 있고, 비공개는 `[비공개]`가 있다.
7. 이미지 폴더를 만들었으면 그 경로가 존재하는지 확인한다. 이미지 파일을 넣었으면 개수가 말한 수와 같은지 확인한다.
8. 결과 보고에는 저장한 절대 경로, `sourceUrl`, `postedAt`, 인덱스 `N / 656`, 검증 결과만 간결하게 남긴다. 보호글 자리표시는 `protected`를 함께 보고한다. 본문이 있는 비공개는 `private`를 함께 보고하고, 주소가 없으면 주소 미확정을 남긴다. 주소만 있는 비공개는 경로와 `postedAt` 없이 `sourceUrl`과 `[비공개]`만 보고한다. 이미지 폴더를 만들었으면 그 경로를 남긴다.
