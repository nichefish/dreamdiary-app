# 엔트리·리플렉션 액션 툴바 구성 (아이디어)

> 상태: **아이디어 (계약 외부)** — 액션 버튼을 사용자가 켜고 끄거나 순서를 바꾸는 "구성 가능한 툴바", 그리고 그 하부의 액션 레지스트리 수렴은 합의된 계약이 아니다. 현재 계약은 고정 배치다(엔트리는 [interaction-spec](../migration/journal/interaction-spec.md) "우측 액션 영역 구조", 리플렉션은 "임베드 Reflection 액션").

## 배경

엔트리 액션 행(`.journal-entry-actions`)과 리플렉션 임베드 액션(`.journal-reflection-embed__actions`)에 상시 노출 컨트롤이 누적되면서 "버튼 영역이 장황하다"는 체감이 생겼다. 직전 정리로 링크 복사(`🔗`)를 복사 `▾` 드롭다운으로 흡수해 상단을 한 칸 줄였다.

## 후보 방향

1. **런타임 구성 가능 툴바** — 사용자가 상단에 노출할 액션·순서를 설정으로 고른다.
2. **내부 액션 레지스트리 수렴** — 사용자용 설정 없이, 액션 목록을 데이터로 한 번 선언하고 행/오버플로(⋯)를 거기서 렌더해 엔트리·리플렉션 두 툴바를 단일 소스로 모은다. 현재 두 툴바는 미묘하게 다르다(엔트리엔 링크 복사, 리플렉션엔 접기 토글).

## 보류 사유 / 트레이드오프

- **런타임 구성 가능**: 사실상 1인 사용자 앱이라 "취향 분기·잦은 변경"이 없어 효용이 낮다. 설정 UI·저장(prefs)·기본값·두 툴바 적용·테스트 비용에 더해, "기본 렌더 vs 설정 반영 렌더"라는 영구 이중 경로가 수렴(convergence) 원칙과 충돌한다. → 현재로선 투머치.
- **액션 레지스트리 수렴**: 사용자 설정 비용 없이 두 툴바 중복을 하나로 모으는 수렴 이득이 있으나, 그 자체가 리팩터라 별도 SAVEPOINT로 스코프해야 한다. 계약화하려면 별도 합의가 필요하다.

## 값싼 대안 (계약 내부에서 처리 가능한 것)

- "상단에 남길 것 vs ⋯로 내릴 것"을 1회 고정 결정하고 두 툴바에 동일 적용. 링크 복사 이동의 연장선이며 config 없이 처리된다.

## 액션 표면 일관성 감사 (1차, 읽기 전용)

> 이 절은 현재 구현을 훑은 **감사 기록**이다. 아래 불일치 해소는 아직 합의된 계약이 아니며(계약 외부), 실제 수정은 항목별로 별도 SAVEPOINT·승인 후 진행한다.

### 액션 표면 인벤토리 (7곳)

| 표면 | 상시 노출 버튼 | 오버플로(⋯/드롭다운) |
|---|---|---|
| 일자 카드 `JournalDayCard` | 챕터 등록 · 일기 등록 · 메타 `bi-bar-chart`(dropup) | — |
| 챕터 헤더 `JournalChapterItem` | 엔트리등록(텍스트) · 복사 split(3) · TXT split(2) · 접기 토글 | ⋯(수정·상태[접기]·삭제) — 요약 챕터는 ⋯ 숨김 |
| 엔트리 `JournalEntryItem` | ⓘ glance · 💬 · 복사 split(full/no-pending/body+링크) | ⋯(새창·수정·해석등록·이력·관련글·스레드·라이프사이클·상태·삭제) |
| 리플렉션 `JournalReflectionItem` | ⓘ glance · 💬 · 복사(단일) · 접기 토글 | ⋯(새창·수정·wrap-noti·이력·스레드·라이프사이클·상태·삭제) |
| 스레드 상세 `JournalThreadDetailPage`/`…Modal` | 복사 split · 다운로드 split · 💬 · 댓글수 배지 | (소속 엔트리는 엔트리 액션 재사용) |
| 스레드 목록 `JournalThreadList` | — | ⋯(항목별) |
| 검색 `JournalEntrySearchPage` | 엔트리 액션 재사용 | 동일 |

### 발견된 불일치

**A. 순수 비주얼 (스타일만, DOM 흐름 불변 — 저비용·저위험)**
- **F1 다운로드 아이콘 폰트 두 세트**: 챕터 `fas fa-download`(`JournalChapterItem.vue`) vs 스레드 `bi bi-download`(`JournalThreadDetailPage.vue`/`…Modal.vue`). 같은 동작·다른 아이콘.
- **F2 ⋯ 아이콘 크기 불일치**: 엔트리·리플렉션 `fs-6`, 챕터·스레드 목록 `fs-2x`.
- **F3 인라인 버튼 스타일 분기**: 엔트리 `journal-entry-action-btn` vs 리플렉션·스레드 `btn-bg-light btn-active-color-primary`(둘 다 인라인). 챕터는 헤더라 `btn-sm…btn-outlined`(정당).

**B. 계약 정합 (동작·의미 통일 필요)**
- **F4 복사 계열 비대칭**: 리플렉션만 split 없이 단일 복사(no-pending/body 없음). 링크 복사는 엔트리에만 있고 챕터·스레드엔 없음.
- **F5 접기 어포던스 3종**: 챕터=전용 토글 버튼+⋯상태(서버), 엔트리=⋯상태 COLLAPSED만(빠른 토글 없음), 리플렉션=인라인 토글 버튼(⋯엔 없음). 위치·성격(클라/서버) 제각각.
- **F6 댓글 표현 상이**: 엔트리·리플렉션은 💬+인라인 표시, 스레드는 💬+댓글수 배지 버튼.

**C. 구조**
- **F7 ⋯ 공통 항목(새창·수정·이력·삭제) 순서·구분선 위치가 표면마다 미세하게 다름.** 근본 해소는 위 「내부 액션 레지스트리 수렴」(표면별 액션을 데이터로 선언→행/⋯ 렌더).

### 추천 진행 순서 (각 = 별도 SAVEPOINT)

1. A그룹 비주얼 통일(F1~F3) — 스타일만, 조작 흐름 불변. 착수 시 UI 변경이라 승인 필요.
2. F4 복사 계열 통일 — "링크 복사를 챕터·스레드에도 / 리플렉션에 split" 계약 결정 선행.
3. F5 접기 어포던스 통일 — 엔트리 빠른 토글 여부 등 정책 결정 선행.
4. F7 액션 레지스트리 수렴 — 위를 근본에서 없애나 리팩터 규모 큼, 마지막.
