# Dreamdiary AI Chat Philosophy

동작 기준과 구현 상태는 [AI Chat Spec](CHAT_AI_SPEC.md)을 따른다. AI 능력과 채팅 채널의 패키지 분리는 [AI_DOMAIN_SEPARATION.md](AI_DOMAIN_SEPARATION.md)를 본다.

## 핵심 관점

Dreamdiary의 AI 채팅은 단순 질의응답 도구가 아니라, 사용자의 기록과 생각을 이어서 다루는 대화형 보조자다.

따라서 가장 중요한 체감 가치는 기능 수가 아니라 **연속성**이다. 사용자는 AI가 이전 맥락을 기억하고 있다고 느끼는 순간부터 상대를 “대화 가능한 존재”로 받아들인다.

## 세션 중심 구조

채팅의 중심 개념은 메시지가 아니라 세션이다.

- `chat_session`: 하나의 대화 흐름
- `chat_message`: 세션에 속한 발화
- `chat_setting`: 사용자/관리자 설정

메시지는 반드시 세션에 속해야 한다. 서로 다른 세션의 맥락은 섞지 않는다. 세션 경계가 곧 기억의 경계다.

## 역할 기반 메시지

`createdBy`는 감사 정보일 뿐, 발화 주체를 판단하는 기준이 아니다.

발화 주체는 `role`로 판단한다.

- `USER`: 사용자 발화
- `ASSISTANT`: AI 응답
- `SYSTEM`: 시스템 지시문

AI 응답이 현재 로그인 사용자 컨텍스트에서 저장되더라도, `role=ASSISTANT`이면 화면과 컨텍스트에서는 AI 발화로 취급한다.

## 기억 전략

초기 기억 전략은 전체 세션 raw 삽입이 아니라 **최근 N개 메시지 기억**이다.

세션 전체를 매 요청마다 모델에 넣는 것은 다음 문제가 있다.

- context 한계
- 응답 지연
- 불필요한 과거 잡음 유입
- 답변 품질 저하
- 로컬 LLM 리소스 부담

따라서 현재 전략은 다음과 같다.

```text
system prompt
+ 같은 세션의 최근 N개 메시지
+ 현재 사용자 질문
```

현재 사용자 질문은 먼저 저장한 뒤 최근 메시지 목록에 포함한다. 같은 질문을 별도로 한 번 더 붙이지 않는다.

## 설정 철학

채팅 설정은 하나의 테이블에서 사용자 설정과 관리자 기본값을 함께 다룬다.

```text
scope      USER / ADMIN
scope_key  username / GLOBAL
```

- 사용자 설정은 즉시 체감되는 값이다.
- 관리자 설정은 전역 기본값과 허용 범위의 성격을 가진다.

`recentMessageLimit`은 사용자 UI에서 바로 조정 가능해야 한다. 이 값은 품질과 속도의 균형에 직접 영향을 주기 때문이다.

## UI 방향

AI 채팅 UI는 필연적으로 ChatGPT류 인터페이스와 닮아간다. 이는 복제가 아니라 대화형 AI UX의 자연스러운 수렴이다.

다만 Dreamdiary는 일반 챗봇이 아니라 기록 기반 보조자여야 한다.

하지만 초점은 “기능을 많이 붙이는 것”이 아니라, 사용자가 자신의 기록을 더 잘 정리하게 돕는 것이다.

## 원칙

- 세션 경계를 넘겨 기억하지 않는다.
- `createdBy`와 `role`을 혼동하지 않는다.
- 전체 대화를 무조건 넣지 않는다.
- 사용자가 체감하는 설정은 채팅창 근처에 둔다.
- 관리자 설정은 기본값과 정책을 담당한다.
- Dreamdiary AI의 정체성은 “기록 기반 개인 보조자”다.
